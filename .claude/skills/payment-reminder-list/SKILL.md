# 未入金督促リストの更新

目的: 入金管理シートと食い違いのない督促リストを保ち、回収状況を社内が一目で分かるようにする。

## 判定と集計のルール

- 入金済みかどうかは、入金管理シートでどの請求月のタブが入金済みになっているかで決める。
- 対象範囲と集計の形はユーザーの指定に従う（例: 翌月利用分は除外、特定の決済手段は別枠で集計のみ、新しい月は別タブ）。迷う行は確認する。
- 新しい月のタブは支払期日の翌日に作る。
- 回収推移は週単位で集計し、シート左上に最終更新日時を書く。合計行の回収率は月別回収率の単純平均にする（指定が変わったら従う）。
- 個別行の金額が元データと食い違うときは確認を求め、指定された値を推移表にも反映する。

## 更新後

- 数式や値を変えたら、監査スクリプトとレビュー用エージェントで元データと照合してから報告する。
- ユーザーが手で変えた値・フィルタ・書式は残す。
- 繰り返す更新は手順を文書化し、定期タスクにできるか提案する。

## 文面

- 社内 Slack の周知は要点だけ（参照シート、更新タイミング、更新箇所、運用ルール）。
- 顧客への督促は、過去に自社がその顧客に送ったやり取りのトーンに合わせる。精算の提案を受けたら「受け取って社内で確認する」とだけ返し、社内の確認事項は別に整理する。
