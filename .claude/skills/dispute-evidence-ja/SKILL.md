# 紛争対応の事実確認とエビデンス整理

目的: 弁護士や取引先との協議にそのまま使える、根拠つきで自社の立場を守る資料を作る。良い資料は、記載ごとに根拠と確認状況が分かり、量が多すぎず、社内向けの分析と外に出す情報が分かれている。

## 進め方

1. 範囲を確かめる: 相手の主張の項目、対象期間、ユーザーが対象外とした資料（使わない）、成果物の形式と保存先（ローカルかクラウドか）。「まとめて」が要約の作成か原本の収集かは確認する。
2. 主張を1項目ずつ一次情報（契約書・申込書・規約・Slack・業務記録）と照合する。不明な点は推測で埋めずユーザーに質問する。
3. 規約の版を特定するときは、申込書の同意文言・締結日と、規約の改定日・適用開始日を照合し、根拠と未確認点を書く。
4. 論点は契約の前提（役割分担・業務範囲）に沿って分類する。人物・部署・役職・雇用形態はユーザーに確かめながら進める。

## 書き方

- 各記載に確認状況（確認済み／一部確認／未確認）と出典を付ける。
- 外に出す資料には自社に有利な事実と、不利に見える点の事業上の説明を書き、不利な記述を列挙しない。リスク評価や社内向けの分析はセッション内の回答に分ける。
- 方針を直したら、同じ内容を含む他の成果物（PDF とドキュメントなど）にも同じ修正を当てる。

## エビデンスと納品

- スクリーンショットは共有ドキュメントに直接貼らない。項目ごとに1つの PDF にまとめ、エビデンスと分かる名前でフォルダに置き、ドキュメントにはファイル名とリンクだけ書く。
- 原本を集めるときは PDF に揃えて1つの Zip にし、日本語ファイル名が文字化けしないようにする。非公開の DM は収集しない。
- 業務履歴の集計は Excel の表で渡し、コメントは表の下に文章で書く。
- 共有ドライブのファイルが閲覧権限のみなら、ローカルに保存して差し替え手順を案内する。
- 契約条件を含むファイルはリポジトリにコミットしない。
