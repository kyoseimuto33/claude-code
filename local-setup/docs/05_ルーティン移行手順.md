# 05. ルーティン（定期実行）の移行手順

## まず決めること: クラウドに残すか、ローカルに移すか

| 観点 | クラウドのまま（推奨） | ローカルへ移す |
|---|---|---|
| PC の電源・スリープ | 関係なく実行される | **PC が起きていないと実行されない** |
| 設定作業 | 不要（今のまま動く） | cron / タスクスケジューラ登録が必要 |
| コネクタ（Slack 等） | 使える | 使える（claude.ai ログイン時） |
| 社内ネットワーク限定のAPI | 届かない | 届く |
| 管理場所 | claude.ai/code/routines | 自分の PC |

ルーティンはクラウド（claude.ai アカウント）に保存されているため、**ローカルで作業を始めても止まりません**。
ローカルの Claude Code からも `/schedule`（別名 `/routines`）で作成・更新でき、Web・デスクトップアプリ・CLI のどこで編集しても同じものが更新されます。

→ 特別な理由がなければ **ルーティンはクラウドに残し**、このパッケージの `routines/` は
「手元で1回だけ実行したい」「設定のバックアップ」「将来ローカルに移す場合」の資材として使ってください。

## 同梱物

```
routines/
├── routines.json                 ← 4つのルーティンの設定（スケジュール・モデル・コネクタ・シークレット名）
├── prompts/                      ← 各ルーティンのプロンプト全文（シークレット除去済み）
│   ├── weekly-ai-trend.md
│   ├── weekly-seo-trend.md
│   ├── archi-dog-popular-ranking.md
│   └── seo-pipeline-monthly.md
├── scripts/popularity_score.py   ← archi-dog 用スクリプト（認証情報は .env から読む版）
├── run_routine.sh / .ps1         ← 1回実行するランナー（Mac・Linux / Windows）
└── scheduler/
    ├── crontab.example           ← Mac・Linux の定期実行設定例
    └── register_windows_tasks.ps1 ← Windows タスクスケジューラ登録
```

### クラウド版からの変更点

| ルーティン | 変更内容 | 理由 |
|---|---|---|
| Weekly ai/seo trend | `mcp__cowork__present_files` の手順を「保存パスを表示」に置換 | ローカルにはこのツールが無い |
| Weekly ai/seo trend | Slack チャンネル ID を `.env` から差し込めるように | プレースホルダのままだった |
| archi-dog | スクリプトを別ファイル化し、認証情報を `.env` から読む | 平文のシークレットを排除。ロジックは一字一句同一 |
| archi-dog | 既定で Claude を介さず `python3` で直接実行 | AI の判断が不要な処理。確実・高速・無料 |
| SEO Pipeline | Basic 認証値を `$FLUMO_API_BASIC_AUTH` 参照に置換 | 平文のシークレットを排除 |

## 手元で1回実行する

前提: 02 の手順が完了し、04 の `.env` に必要な値が入っていること。

**macOS / Linux**
```bash
cd ~/claude-local-setup
./routines/run_routine.sh weekly-ai-trend
./routines/run_routine.sh archi-dog-popular-ranking
```

**Windows**
```powershell
cd $HOME\claude-local-setup
powershell -ExecutionPolicy Bypass -File .\routines\run_routine.ps1 weekly-ai-trend
```

- 実行ログ: `routines/logs/<ルーティン名>_<日時>.log`
- トレンド資料: `outputs/`
- 許可モードは `dontAsk`（あらかじめ許可したツール以外は自動で拒否。無人実行で止まらない）
- モデル指定を変える: `ROUTINE_MODEL=sonnet ./routines/run_routine.sh ...`
  （`claude-sonnet-4-6` など古いモデル ID が使えなくなった場合もこれで上書き）
- archi-dog を Claude 経由で実行: `USE_CLAUDE=1 ./routines/run_routine.sh archi-dog-popular-ranking`

> ⚠️ archi-dog と SEO Pipeline は**本番の Shopify / API を書き換えます**。クラウド側も有効なまま手元で実行すると、
> 同じ処理が2回走ります（結果は同じになる設計ですが、意図しない実行に注意）。

## ローカルで定期実行する（完全移行する場合）

1. 上記「手元で1回実行する」で正常終了を確認
2. 定期実行を登録
   - **macOS / Linux**: `crontab -e` で `routines/scheduler/crontab.example` の内容を貼り付け（`CLAUDE_LOCAL` を展開先の絶対パスに）
   - **Windows**: `powershell -ExecutionPolicy Bypass -File .\routines\scheduler\register_windows_tasks.ps1`
   - **デスクトップアプリ**: Code タブ → Routines → New routine → 「Local」を選ぶと、PC 上で動く定期タスクを GUI で作れます
3. **クラウド側の同じルーティンを無効化**（claude.ai/code/routines → 対象 → 無効化）。二重実行防止
4. 翌週、ログ（`routines/logs/`）と Slack 配信を確認

| ルーティン | クラウドの設定 | ローカルの登録時刻（PC が日本時間の場合） |
|---|---|---|
| Weekly ai trend | `CRON_TZ=Asia/Tokyo 0 10 * * 1` | 月曜 10:00 |
| Weekly seo trend | `CRON_TZ=Asia/Tokyo 0 10 * * 1` | 月曜 10:10（同時起動を避けて10分ずらし） |
| archi-dog 人気商品ランキング | `7 17 * * 0`（UTC） | 月曜 02:07 |
| SEO Pipeline（クラウドで無効中） | `0 15 * * *`（UTC） | 毎日 00:00（既定では登録しない） |

### ローカル定期実行の注意

- 深夜帯（archi-dog 02:07、SEO Pipeline 00:00〜05:30）は PC がスリープしていると動きません。
  Windows は `StartWhenAvailable` で復帰後に実行されます。cron は実行されずスキップされます
- SEO Pipeline は最長 5.5 時間かかる長時間ジョブです。ローカル化するなら常時稼働のマシンで
- Windows で SEO Pipeline を動かすには Git Bash か WSL が必要です（プロンプトが bash 構文の curl/sleep を使うため）

## クラウドのルーティンを CLI から管理する

```text
/schedule                      ← 対話形式で新規作成
/schedule update               ← 既存ルーティンの変更（cron 式の直接指定も可）
```
最小間隔は1時間。API トリガー（外部から起動する URL）の追加は Web（claude.ai/code/routines）から行います。
公式: https://code.claude.com/docs/en/routines
